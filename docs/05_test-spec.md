## 1. この文書について

### 1.1 目的

要件定義書の受け入れ基準（9章）の「4章のすべての機能が、テスト仕様書のテストに合格している」の **テスト仕様書** にあたる。
何を・どの条件で・どうなれば合格とするかを、テストの ID ごとに定める。

### 1.2 進め方

- テストは **自動テスト（pytest）** で書き、`uv run python scripts/check.py` と CI で毎回実行する
- 実装の Issue ごとに、その Issue で作った機能のテストをこの文書に書き足す（実装と同じ PR に含める）
- DB 設計書 5章の計算の例は、**そのままテストの期待値**にする
- 画面の見た目や操作感のように自動テストにしにくいものは、「手動」と書き、確認した日と結果を残す

### 1.3 テストの ID

| 接頭辞 | 対象 | 例 |
|---|---|---|
| `T-DB` | DB の制約と初期データ | T-DB-01 |
| `T-SV` | サービス層の計算・業務ルール（追加予定） | T-SV-01 |
| `T-SC` | 画面（追加予定） | T-SC-01 |
| `T-BT` | バッチ処理（追加予定） | T-BT-01 |

### 1.4 テストの環境

| 項目 | 内容 |
|---|---|
| DB | MySQL 8.4.11（手元は Docker、CI は GitHub Actions のサービス）。本番の RDS と同じバージョン |
| テスト用の DB | テストのたびに `test_budget` を作り、マイグレーション（初期データを含む）を適用してから実行する |
| データの後始末 | 各テストは DB の更新を取り消して終わる（pytest-django の `django_db`）。テストどうしが影響しない |
